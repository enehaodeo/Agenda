# 日程 · 手工排程

一个本地优先的日程表 App。白天宣纸朱砂、夜里灯下研墨，无需安装；不登录就是纯本地，数据只存在你自己的浏览器里；登录账号后可在电脑、手机之间自动同步。

## 怎么打开

双击 `index.html` 即可（推荐 Chrome / Edge）。

如果想用本地服务器打开（数据存储更稳妥，也便于手机在同一 Wi-Fi 下访问），双击 `启动.cmd`，浏览器会自动打开 <http://localhost:5177>。

## 账号与多设备同步

- **不登录**：和以前完全一样，数据只在这台浏览器里，不发任何网络请求。
- **注册 / 登录**：点右上角 `登录`。注册填邮箱和密码（至少 6 位），邮箱会收到一个验证码，填进去就完成了；忘记密码也是同样的验证码流程。整个过程都在页面里完成，双击 `index.html` 打开也能登录。
- **自动同步**：登录后每次改动照旧先存在本机，1.5 秒后推到云端；页面回到前台、恢复联网、以及每隔一分钟也会拉一次别的设备的改动。右上角按钮显示当前状态：`已同步`／`同步中`／`离线`／`未同步`／`需登录`，鼠标停上去能看到详情。
- **断网**：照常使用，按钮变成朱砂色的 `离线`，并提示「改动会先存在本机」；联网后自动补同步。
- **两台设备改了同一处**：同一条任务以后改的为准；一边删了、一边改了，保留改过的；两边在同一时段各排了一件事，较早排的那件会退回待办，并提示你。
- **第一次登录**：如果这台设备上还有没登录时记下的任务，会问你要不要「并入账号」（可撤销）。
- **退出登录**：回到未登录时的那份数据。账号数据默认留在本机（下次登录秒开），公用电脑上可以勾选「退出时清除本机上这个账号的数据」。
- **注销账号**：在账号对话框里，会永久删除云端数据。

## 六件事怎么做

| 功能 | 操作 |
|---|---|
| **① 添加任务** | 左上角写名称 → 填时／分（或点 15/30/45/60/90 快捷键）→ 选标签 → `添加到待办`。回车也能提交。事后点任务上的 `✎` 随时改名称、耗时、标签、备注。 |
| **② 拆分任务** | 打开任意任务的 `✎`，在「拆分为子任务」里 `＋ 添加子任务`，每条子任务各有自己的耗时和标签。右上角实时显示「合计 / 计划 · 剩余或超出」。拆分后父任务变成一个分组，改为分别安排各子任务。 |
| **③ 选取可用时间** | 右侧 `＋ 时间段` 填起止时间（精确到分钟），或用「上午／下午／晚间／全天」预设；也可以**直接在时间轴空白处按住鼠标上下拖动**刷出一段。拖时间段的上下边缘可以拉伸，`×` 删除。`沿用昨日` 一键复制前一天。 |
| **④ 放入日程表** | 把左侧任务**拖进时间轴**——会自动吸附到 5 分钟刻度、时间段边界和相邻色块边缘，且不会重叠、不会越出可用时间。嫌麻烦就点任务上的 `↳` 自动排入最近空档，或点 `自动排程` 一次性铺满。已排的色块还能继续拖动改时间。 |
| **⑤ 本日日程** | 打开就是今天：顶部显示当日日期与实时走秒的时钟，时间轴上有一条跟着走的朱砂色「此刻」线。`‹ ›` 或点日期可翻到别的日子，`今天` 一键回来。 |
| **⑥ 完成 / 未完成** | 色块上的 `✓`＝完成，任务从系统里删除并记入左下「已完成」；`↩`＝未完成，退回待办等你重新分配。右上角 `结算` 会集中列出所有**已经过时**的日程（按钮上带红色角标），逐条选择完成／未完成／顺延到今天最近的空档。 |

## 其他

- **导览**：第一次打开会自动放一遍十一步导览，把上面六件事和几条机制走一遍。之后随时点右上角 `导览` 重看，`←` `→` 翻页，`Esc` 或「跳过」退出。导览全程只是看，不会改动任何数据。
- **夜间模式**：右上角第一颗按钮循环切换 `随系统` → `浅色` → `深色`。默认跟随系统——系统切到深色，页面当场跟着换上墨色一套，不用刷新；手动选定后就一直按你选的来。这项设置只记在这台设备上，不进备份。
- **撤销**：`Ctrl+Z` 或点右上角「撤销」。删除、完成、清空、自动排程等都可以回退。
- **快捷键**：`N` 聚焦新建框，`T` 回到今天，`←` `→` 翻天。
- **手机上**：两栏收成两页，底栏在 `待办` 和 `日程` 之间切换，中间的 `＋` 直接去写新任务。待办里点 `↳` 排入后会翻到日程页给你看。时间轴上划动是滚动，**点一下**色块露出 ✓ ↩ ✎，**长按**色块再拖才是改时间。外观、撤销、导出导入、导览收在右上角 `⋯` 里。
- **备份**：右上角 `导出` 存一份 JSON，`导入` 恢复。换电脑或清浏览器缓存前记得导出。
- **数据位置**：浏览器 localStorage。未登录的数据在 `agenda.v1`；登录后每个账号一份 `agenda.u.<账号id>.v1`，同步记录在 `agenda.u.<账号id>.sync.v1`，登录会话在 `agenda.acct.v1`（外观存 `agenda.theme.v1`，导览记录存 `agenda.tour.v1`，都不进备份）。不登录时，换浏览器 = 换一套数据。
- **离线可用**：未登录时 **0 个外部请求**，不联网、不依赖任何 CDN；登录后也只连你配置的 Supabase 地址。拉丁字体（Fraunces 标题、IBM Plex Mono 数字，仅 latin 子集共 95 KB）内嵌在 `fonts.css` 里，`file://` 双击打开也不会被 CORS 拦；中文用系统已装的 Noto Serif SC / Noto Sans SC，没装的机器依次回落到思源宋体、宋体、微软雅黑。

## 文件

```
index.html    页面结构
fonts.css     本地字体（内嵌 data URI，127 KB）
styles.css    样式（深浅两套配色变量都在文件顶部的 :root 里）
app.js        全部逻辑：数据模型、排程算法、拖拽交互
sync.js       账号与云同步（Supabase，纯 fetch，无依赖）
supabase/     云端建表脚本 schema.sql
fonts/        字体原始 woff2，仅作留档，页面不引用
启动.cmd      用 Python 起一个本地服务器并打开浏览器
```

## 启用云同步（部署的人看一次就行）

不配置也完全能用，只是右上角的 `登录` 会提示「还没配置云同步」。要启用：

1. **建 Supabase 项目**：到 <https://supabase.com> 新建项目，区域选 Singapore 或 Tokyo（离大陆近）。
2. **建表**：控制台 → SQL Editor，把 [`supabase/schema.sql`](supabase/schema.sql) 整段粘进去执行。它建一张 `agendas` 表（每个账号一行），开启行级权限（每人只能读自己的），外加两个函数：`push_agenda`（带版本号的推送）和 `delete_me`（注销账号）。
3. **邮件用验证码**：Authentication → Emails → Templates，把「Confirm signup」和「Reset password」两个模板里的链接换成验证码，例如：

   ```html
   <p>你的验证码是：<b>{{ .Token }}</b>，10 分钟内有效。</p>
   ```

   （验证码而不是链接，是因为双击打开的 `file://` 页面收不到链接的回跳。）同时确认 Authentication → Sign In / Providers → Email 里开着「Confirm email」。
4. **配置发信（开放注册必做）**：Supabase 自带的发信每小时只有个位数额度，到 Authentication → Emails → SMTP Settings 接入自己的发信服务（如 Resend、阿里云邮件推送、腾讯云 SES）。
5. **填配置**：Project Settings → API（或 API Keys），把 Project URL 和 anon / publishable key 填进 `sync.js` 顶部的 `SUPABASE_URL`、`SUPABASE_ANON`。这个 key 本来就是公开的，数据安全靠第 2 步的行级权限。
6. **放到网上给手机用**：GitHub 仓库 → Settings → Pages → Source 选 `Deploy from a branch`，分支 `master`、目录 `/ (root)`。几分钟后手机浏览器打开 `https://<用户名>.github.io/Agenda/` 登录即可。然后回 Supabase：Authentication → URL Configuration → Site URL 填这个地址。

注销账号依赖 `delete_me` 删除 `auth.users` 里的记录；如果你的 Supabase 项目限制了这项权限导致注销失败，可以在控制台 Authentication → Users 手动删除该用户，云端数据会随之级联删除。
